# Phase 8 — Private research inference API

## Decision

The current validation evidence does not justify making an ML score a clinical priority signal. Phase 8 packages the **HistGradientBoosting research reference** behind a private, read-only API. XGBoost remains a challenger artifact. The API returns only an uncalibrated model score and target metadata; it does not return a recommended priority, ICU eligibility, a cutoff-based alert, or an allocation instruction.

## What this service does

- `GET /health`: readiness only; no model feature values are exposed.
- `GET /v1/model-info`: API-key protected metadata about the model, feature names, and research target.
- `POST /v1/predict`: API-key protected score calculation. Input is an object containing any subset of the exact numeric model features; omitted/null values are treated as missing as the trained pipeline supports missing values.
- Rejects unrecognized fields (including `patient_id`), strings, booleans, infinities, unknown features, all-missing requests, incompatible schema/metadata, and a model that doesn't expose positive class `1`.
- Does not persist input data, send data to analytics, change patient records, change queue/bed status, or make an admission decision.
- Reports feature completeness and target semantics with every score.
- API documentation is disabled when `BEDALLOCATION_ENV=production`.

## Security boundary

Keep this API on localhost or a private service network. Do not expose port 8001 publicly. Configure a random API key of at least 32 characters and pass it only server-to-server in the `X-API-Key` header. Do not put this key in any `NEXT_PUBLIC_*` variable or browser JavaScript. A later Express proxy can authenticate the signed-in user and call this service server-to-server, but must not feed the score into queue ranking or allocation.

Load only model artifacts created by this project from trusted files. `joblib` deserialization can execute code; never load a model file supplied by an untrusted user. This API assumes the six-hour corrected-target schema generated by `prepare_dataset.py` and checks it against the model metadata before startup.

## Install the API extra

From `ml-service` with the project's Python environment active:

```powershell
python -m pip install -e ".[api,test]"
```

## Configure the local service

Use the current corrected target files and research reference artifact:

```powershell
if (!(Test-Path .ml-api-key.local)) {
  python -c "from pathlib import Path; import secrets; Path('.ml-api-key.local').write_text(secrets.token_urlsafe(48), encoding='utf-8')"
}
$env:BEDALLOCATION_ML_API_KEY = (Get-Content .ml-api-key.local -Raw).Trim()
$env:BEDALLOCATION_ENV = "development"
$env:BEDALLOCATION_MODEL_PATH = "artifacts_onset/sepsis_onset_next_6h_hist_gradient_boosting.joblib"
$env:BEDALLOCATION_SCHEMA_PATH = "data/processed_onset/schema.json"
$env:BEDALLOCATION_MODEL_METADATA_PATH = "artifacts_onset/sepsis_onset_comparison_model_metadata.json"
$env:BEDALLOCATION_MODEL_KEY = "hist_gradient_boosting"
$env:BEDALLOCATION_MODEL_VERSION = "research-candidate-v1"
uvicorn bedallocation_ml.inference_api:app --host 127.0.0.1 --port 8001
```

The local key is stored in `.ml-api-key.local`, which is ignored by Git. It is a local development convenience, not a production secret-management system. In a second terminal, load the same key with `$env:BEDALLOCATION_ML_API_KEY = (Get-Content .ml-api-key.local -Raw).Trim()`. Do not share or commit this file.

### Alternative: XGBoost challenger

To serve XGBoost instead, set both the artifact path and its matching metadata path:

```powershell
$env:BEDALLOCATION_MODEL_PATH = "artifacts_onset/sepsis_onset_next_6h_xgboost_weighted.joblib"
$env:BEDALLOCATION_MODEL_METADATA_PATH = "artifacts_onset/sepsis_onset_xgboost_model_metadata.json"
$env:BEDALLOCATION_MODEL_KEY = "xgboost_hist_weighted"
```

Restart the process after changing settings.

## Test endpoints locally

Open `http://127.0.0.1:8001/health`. In development only, use `http://127.0.0.1:8001/docs` for the schema. Protected requests require the header `X-API-Key`.

Example PowerShell request:

```powershell
$headers = @{ "X-API-Key" = $env:BEDALLOCATION_ML_API_KEY }
$body = @{
  features = @{
    HR = 90
    O2Sat = 96
    Temp = 37.1
    SBP = 118
    MAP = 82
    DBP = 72
    Resp = 18
  }
} | ConvertTo-Json -Depth 5
Invoke-RestMethod -Method Post -Uri "http://127.0.0.1:8001/v1/predict" -Headers $headers -ContentType "application/json" -Body $body
```

The response is an **uncalibrated research score**. Because the app currently records far fewer than the 40 source model features, the service reports missing-feature count and low completeness. Never infer missing measurements. The score is not suitable for routing patients or clinical alerts.

## Verification

```powershell
python -m pip install -e ".[api,test]"
python -m unittest discover -s tests -v
```

The unit tests use a deterministic fake model and do not require patient data or the trained model artifact. Separately verify service startup with the actual local artifact and schema; no claim of a clinical validation is made.
